# Godstone Coherence Audit

Generated by a 6-agent read-only audit of the extracted repository against the
`Godstone.xlsx` spec tabs. Purpose: determine what the workbook actually
delivers versus what it references, so the gap between "documented" and
"compilable" is explicit and evidence-grounded.

**Headline:** the workbook is a deep architectural scaffold. The hard
subsystems are fully written and internally consistent. But two shared modules
are declared yet empty, several facades and most UI screens are referenced but
absent, build plumbing is missing, and four test files target a different API
than the shipped implementation.

---

## What is verified CONSISTENT (the backbone is sound)

- **JNI bridge** — `godstone_llm_jni.cpp` native method signatures exactly match
  `LlamaBridge.kt` external declarations.
- **C1 (no network)** — Android manifest removes `INTERNET` (`tools:node="remove"`);
  iOS has zero `URLSession`/`NSURLSession`/`URLRequest` references.
- **Hilt wiring** — `@HiltAndroidApp` / `@AndroidEntryPoint` / `@HiltViewModel` /
  `@Module`/`@InstallIn` + `hilt-compiler` / `hilt-navigation-compose` deps coherent.
- **BuildConfig** — `MODEL_FILE`/`CTX_TOKENS`/`ARCHIVE_FILE`/`TOP_K_CHUNKS` defined
  in all three flavors with correct types and consumed correctly by `AppModule`.
- **Tier numbers** — identical across `build_archive.py`, Gradle flavors,
  `TIERS.md`, `fetch_models.sh`, `quantise.sh` (qwen3-0.6b/1.7b/4b, ctx 2048/4096/8192,
  embed_dim 384/384/768, bge-small for LIGHT+MEDIUM, bge-base for LARGE).
- **Content pipeline** — `build_archive.py` imports `chunker.Chunk`/`chunk_document`
  and `embedder.Embedder` with matching signatures; all INSERT column lists match
  `schema.sql`; `indexes.sql` applied after inserts; seed docs carry all
  `REQUIRED_FRONT_MATTER`; `meshsim/run.py` imports `scenarios` correctly.
- **Extraction fidelity** — all 76 emitted files match the workbook column-A
  source byte-for-byte (0 line mismatches).

## Category E — Test-vs-implementation inconsistencies (tests won't compile)

- **`RouterTest.kt` (Android) / `RouterTests.swift` (iOS)** — both construct a
  `Router(selfKey:...)` with `onReceive`/`send`/`pendingCount`/`onPeerAvailable`/
  `onBatteryLevelChanged` returning a result with `.shouldRelay`/`.shouldDeliver`/
  `.frame`, and a `Frame(messageId:destination:ttl:payload:)`. Shipped `Router`
  has `onFrameReceived`/`forwardCopy`/`framesPeerLacks`/`currentDigest`/`buildSos`
  and `Frame` has `msgId` (no `destination`). Different constructor, methods,
  return types, field names.
- **`NoiseSessionTest.kt`** — calls `initiator(identity)` (1 arg) vs shipped
  `initiator(identity, localHint, remoteHint)` (3 args); `writeMessage` vs
  `writeHandshakeMessage`; expects `handshakeHash` property and
  `AuthenticationException` that the impl never declares/throws; treats
  `decrypt` as non-null while impl returns `ByteArray?`.
- **`RagPipelineTest.kt`** — uses `RetrievedChunk` (with `section`, `Float`
  score) vs shipped `Chunk` (no `section`, `Double`); calls
  `PromptBuilder(contextTokens, reservedForAnswer)` as a class with
  `build(question, List<RetrievedChunk>)` + `estimateTokens()` vs shipped
  `object PromptBuilder.build(question, RetrievalResult)`; imports `kotlin.test.*`
  while `build.gradle.kts` only provides JUnit 4.

## Category F — Cross-layer API inconsistencies (production caller vs callee)

- **iOS `RagPipeline`** — `AppContainer` constructs `RagPipeline(models:retriever:topK:)`
  and `OracleViewModel` calls `retrieve`/`warmUp`/`generate`/`extractCitations`/
  `release`; but `RagPipeline` only offers `init(retriever:builder:)` and
  `answer(question:onToken:) -> RagOutcome`. Three different API shapes across
  tabs 06/08 for one type.
- **iOS `ModelManager`** — `AppContainer` calls `ModelManager(modelName:contextTokens:)`
  but it has `private init()` + `static let shared`.
- **iOS `Package.swift`** — no App/executable target; `Sources/App/*` (incl.
  `@main GodstoneApp`) belong to no product.
- **Android `MeshNode` acquisition** — `MeshService` uses `MeshNodeHolder.get(ctx)`
  while the rest of the app uses Hilt `@Inject`; two strategies for one singleton.

## Category G — Spec drift / unimplemented protocol requirements

- **Sealed sender + daily-rotating routing tags** — unimplemented; `Frame` has no
  destination/routing-tag field.
- **`msg_id` = BLAKE2s-64(payload||sender||timestamp)** — unimplemented; `msgId`
  is a caller-supplied `Long`.
- **TOFU key pinning** — unimplemented.
- **Token-bucket rate limits + per-node trust scoring** — unimplemented.
- **24h session cache** — unimplemented; sessions created per call.
- **SOS 30-day retention / evicted last** — unimplemented; uniform 14-day `MAX_AGE`.
- **BLE epoch = minutes since boot** — code uses minutes since Unix epoch
  (`BleTransport.kt:89`).
- **SOS_ACTIVE continuous scan** — code uses 300 ms windows (`Transport.kt:56`).
- **RAG confidence threshold parity** — iOS `0.28` vs Android/tests `0.35`; the
  tab-12 parity test would fail.
- **Content** — `sources.yaml` never read by code despite claiming build-time
  enforcement; `content/seed/vendor/` missing; `requirements.txt` lists
  `markdown-it-py`/`textstat`/`numpy` (none imported); `dequantise_int8` dead;
  architecture tab says chunk overlap 80 / LARGE dim 384 but code uses 48/64 and
  768.
- **CI** — README uses `python -m ingest.build_archive` while CI/code use
  `content.ingest.build_archive`; `check_tiers.py` runs without `--require-swift`
  so the iOS tier table is never enforced.
